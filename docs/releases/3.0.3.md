# ArguLab v3.0.3

**Release: v3.0.3**

22 November 2026 · Compatible resource optimizations and Neon PostgreSQL migration.

## Shipped behavior

- PostgreSQL runs on Neon using verified direct connections. The migration tooling preserves accounts, password hashes, encrypted tokens and practice records, and refuses an occupied target.
- Ordinary cloud saves use 30-second checkpoints. Local drafts remain prompt; submitted turns, completion and leaving practice flush immediately. Background checkpoints pause, unchanged snapshots are suppressed and newer edits survive in-flight acknowledgements.
- History/reset reads and owner/reset checks use fewer SQL round trips. Rate quotas remain atomic in PostgreSQL; bounded housekeeping is coalesced and targeted indexes support expiry/community queries.
- Cursor pagination uses the existing owner/id index and explicit end-of-history metadata while retaining offset compatibility. Local history is revalidated after external storage changes rather than reparsed on every unchanged read.
- Structured AI requests repeat only recoverable generated-JSON failures. Permanent configuration/authentication errors stop immediately; the shared evaluation rubric precedes variable content. Model choice, output bounds and complete transcript context remain unchanged.
- CI cancels obsolete runs for a ref, caches registry packages, excludes duplicate tag-push runs and retains failure artifacts for seven days. Isolated mocked-provider and browser checks cover the changed behavior.
- Footer, policy subtitles and refund-page text now share the generated release version. The existing policy-consent date remains separate and unchanged.

## Verification and limits

Local verification passed **90 backend/integration tests, 35 browser tests and four release-tool tests**, build, types, persistence/import/migration regressions, client credential scans and isolated query-plan comparisons. Lint passed with 13 existing warnings and no errors. The unit suite's loaded-module coverage measured 85.18% lines and 80.06% functions; it is not whole-frontend browser coverage. GitHub CI verifies the pushed source commit separately; the public companion contains documentation only.

An existing ten-minute timer-only browser simulation produced 19 cloud checkpoints versus approximately 200 under the earlier cadence. The synthetic deep-history comparison checks that cursor and offset pages return identical records while the cursor scan visits fewer rows. These fixtures establish specific resource improvements, not a 70-user production capacity guarantee. Provider caching remains automatic and cache hits are not guaranteed.

## Upgrade and rollback

Deploy both workspaces from the same tested v3.0.3 commit. Confirm `/api/health` reports `version: "3.0.3"`. Preserve `DATABASE_URL`, `AUTH_SECRET`, `SESSION_SECRET`, existing cookie names, policy versions and provider settings. An existing provider migration must follow the separate verified transfer procedure before switching database URLs.

The changes are additive: older offset clients remain supported and newer clients can read older servers. Existing data and the prior additive indexes remain compatible with an application rollback. No paid provider upgrade, merchant configuration or customer billing is required.

## Next milestone

Payment functionality is planned for **v4.0.0**. Its proposed prepaid-credit ledger, provider-budget reservations, payment verification and settlement controls remain future work; this release does not activate them.
